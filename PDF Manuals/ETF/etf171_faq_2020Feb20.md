Q In what instance would the Est Value of [[Cash-in-Lieu]] comp/CU equate to zero when all 
components in the portfolio are non-[[DTCC]] eligible (that is, all have the CIL flag active) but there 
is a value for the Est T-1 Cash amt/CU? 
A Not all non-US domiciled components are included in the estimated value of [[Cash-in-Lieu]] components per 
creation unit. These are considered in-kind exchanges, meaning that there may be no cash exchanged 
at [[settlement]] (aside from the cash component, Est T-1 Cash amt/CU). 
Q Does the [[ETF]] PCF File contain full fund holdings? 
A No, the [[ETF]] PCF file is a representative basket or [[pro rata]] slice of the full fund holdings related because 
of some of the activities that could occur in the answer to the cash in lieu (CIL) question. 
Q What [[DO]] I need to [[DO]] if I cannot gain access to the [[ETF]] portal? For example, if I forgot my user 
name or need to reset my password. 
A Reach out to the CSC at 1-800-253-2488 ([[Option]] 1) to reset your password. Let them know that you 
need help logging into the [[ETF]] portal, and provide the following information: 
• Name
• Company
• User name (if you have it)
• Account number (if you have it)
Q Will the Fixed Income portfolios have components with symbols? 
A No, tickers don’t exist for fixed income. They can be identified through the [[CUSIP]]/ISIN. 
Q In Foreign portfolios, why [[DO]] some of the SEDOL/ISIN fields contain a zero (0) or incorrect data?  
A [[ETF]] agents can submit either the ISIN or SEDOL number. In most situations, [[ETF]] agents provide both. If 
one of the values is not submitted for a component, a zero is generated. If the component does not have 
a registered ISIN or SEDOL number, the agent and product sponsor may provide a dummy  value. [[NSCC]] 
only validates components that are registered as a U.S. security and contains a valid ISIN. Except for 
that, [[NSCC]] does not validate the ISIN or SEDOL number and cannot guarantee its accuracy.  
If the component does not have a registered ISIN or SEDOL number or if these are not specifically 
provided to [[NSCC]] by the [[ETF]] sponsor or agent, the U.S. ISIN may be listed rather than an ISIN identifier 
from a foreign venue. Foreign Portfolios (Global Portfolios): These portfolios pertain to U.S. Exchange 
listed ETFs. An example is the iShares MSCI Japan Fund, EWJ, which contains components that are 
ineligible for [[settlement]] at [[NSCC]] or [[DTC]]. 
Q When are the files transmitted? 
A The service level agreement for distribution of the primary file is at 10:00 P.M. Eastern Time (T-1) and 
includes custom portfolios for authorized participants entitled to these portfolios. A single supplemental 
file is distributed no later than 1:00 P.M. Eastern Time although it is generally available by 12:30 P.M. 
Eastern Time on T.

Q Why [[DO]] symbols and CUSIPs for components not appear on the [[Asset]] in the master file? 
A Occasionally, there are [[ETF]] portfolios that have components that are experiencing a corporate action. 
To process the portfolio, we must derive a user ticker symbol and [[CUSIP]]. These user tickers may 
include ZZZZs or XXXXs at the end of the symbol or contain numeric. 
In addition, when an [[ETF]] has a corporate action where the trading symbol remains the same, but a new 
[[CUSIP]] is assigned, for example in a reverse or regular [[Stock]] split, for [[NSCC]] to distribute the correct 
portfolio the evening before effective date a temporary symbol, not used in the market, is created by 
using the first six digits of the new [[ETF]] [[CUSIP]] along with the new post-split [[shares]] [[CUSIP]]. For example, 
if the effective date for the post-split [[shares]] is December 19, 2014, on the evening of December 18, 2014 
for trade date of December 19, 2014 the PCF will contain this temporary symbol along with the new 
trading [[CUSIP]], while the PCF distributed the evening of December 17, 2014 for trade date December 
18, 2014 will contain the existing market trading symbol and the old [[CUSIP]]. This is necessary because 
[[NSCC]] still needs to process any creation and redemptions on December 18, 2014 for the pre-split [[ETF]] 
[[shares]] that exist in the old [[CUSIP]] and trading symbol while distributing the new post-split portfolio and 
the new [[CUSIP]]. 
Q How does [[NSCC]] calculate cash amounts? 
A All the cash amounts are submitted to [[NSCC]] by the [[ETF]] agents and [[NSCC]] redistributes the information 
to its subscribers. We cannot validate the [[issuer]], sponsor, or agent’s calculation. However, key 
definitions beyond what is available in the file formats is included in this document. For more information 
about a calculation, contact the [[ETF]] agent or [[issuer]] for that [[ETF]]. 
Q Does the PCF contain the [[ETF]] Trading symbol or the iNAV (Intraday Net [[Asset]] Value) s ymbol? 
A The Portfolio Composition File (PCF) file contains the [[ETF]] Trading symbol. 
Q What does it mean if we receive a zero (0) in the cash amounts for a particular [[ETF]] portfolio in the 
header record? 
A When a portfolio is not submitted, the previous day’s portfolio is carried over and zero out the case 
amounts. We use the previous day’s PCF and zero out the Estimated T-1 Cash Amount per CU, 
Estimated Value of CIL Components per CU, NAV per CU, Total Cash Amount per CU, Dividends 
Outstanding per [[ETF]] various cash amounts, and Total [[shares]] Outstanding per [[ETF]]. This alerts 
subscribers that the previous business days file will be used should any creation or redemptions occur 
for the [[ETF]]. In addition, when using a prior day’s portfolio, field 30 of the Type 2 Portfolio Header Record 
is identified with a Y. We plan to expand this capability for portfolios designated as “ cash only” in 2015. 
Also, we advise the customers in the [[ETF]] Portal “submission type” of the browser and field “Prior Day’s 
Portfolio being used” that it is a prior day’s portfolio.

Q How are newly launched ETFs designated? 
A This is a decision made by the product sponsor and the [[ETF]] agent. Generally, if the basket components 
are ineligible to clear through [[NSCC]] and [[DTC]], they are designated a Foreign Portfolio. In the case of 
ETFs that contain corporate, municipal, mortgage-backed, and U.S. government fixed income [[securities]], 
they are almost always designated as a Domestic Portfolio. 
Q H ow can I identify when a newly launched [[ETF]]’s portfolio is added to the Consolidated PCF?  
A When a new [[ETF]] is added to the PCF file you see a value Y (for yes) in field 33 in the Type 2 - Portfolio 
Header Record. There may be instances where a sponsor and [[ETF]] agent provide the portfolio before it 
has begun trading. This designation remains until the first day of trading in the new [[ETF]] begins. When 
new components are added to an existing [[ETF]]'s portfolio in the PCF file, you see a value N (for new 
security) in field 10 in the Type 3-Detail Component Record. 
You also receive live e-mail alerts whenever a new portfolio is added to your subscription. However, you 
must subscribe to ALL in the portal/auto-subscribed, and you must make sure you add a valid email 
address in the Contact Management section of the [[ETF]] Portal located at the top under Update Profile. 
Q Does the domestic portfolios contain the closing price of the components? 
A No. The PCFs are distributed the night before trade date or T-1 and apply to tomorrow’s portfolio; 
therefore, they [[DO]] not include the closing price of the components. 
Q Are all U.S. exchange listed ETFs available in the [[NSCC]] [[ETF]] Portfolio Composition files? 
A Virtually every U.S. listed [[ETF]]’s portfolio are in the file, including the converted HOLDRs product to an 
[[ETF]] structure. Exchange Traded Notes and ETFs that are backed by physical commodities, such as 
GLD and SLV, are unavailable because there is no portfolio to distribute and the price of the commodity 
is quoted in real-time. 
Q Is the Exchange indicator available in the [[ETF]] Portfolio Composition file? 
A No, this information can be obtained from the listing marketplaces themselves and the market of 
execution of the component does not have any relevance when creating and redeeming ETFs.  
Q For components domiciled outside of the United States, does [[DTCC]] receive any international 
exchanges indicators? 
A No, since these [[securities]] are [[NSCC]] and [[DTC]] ineligible, we [[DO]] not classify the 
Q What is a custom portfolio? 
A A custom portfolio is used when an authorized [[participant]] has restrictions on what components it can 
own in a standard portfolio. The components are typically replaced with the estimated cash value of the 
component. The agent and the [[ETF]] are responsible to provide the custom portfolio to [[NSCC]] in one of  
two ways. They can either provide the clearing members number or, if the agent wants to distribute the 
custom portfolio to all authorized participants, they can use the LIST feature when they transmit. 
Regardless of how the custom portfolio is received, the [[ETF]] application automatically provides this 
information to those users that are authorized to receive it from the [[ETF]] agent.

Q What are supplemental files? 
A Supplemental portfolio files exist because a sponsor or agent has determined that they need to correct a 
previously submitted [[ETF]] portfolio or they failed to submit an [[ETF]] portfolio (on T -1) and [[DO]] not want to 
use the prior days portfolio for distribution and creation and redemption processing on T. In these 
instances, the [[ETF]] browser is updated immediately upon receipt of the new [[ETF]] portfolio, an email alert 
is provided for those users who have updated their profile in the browser with a final data file that is 
transmitted no later than 1:00 P.M Eastern Time. that is used for that day’s creation and redemption 
processing. The supplemental data file only contains any new submission and not a redistribution of the 
previous (T-1) file. 
Q When does the When Issued indicator field apply in the PCF? 
A The WI indicator only applies to the component because ETFs [[DO]] not trade on a WI basis. When an [[ETF]] 
splits or reverse splits, the listing market and the sponsor will request the issuance of a new [[CUSIP]] 
number to identify the post-split [[ETF]] security. The WI indicator may exist for a component although 
industry practice has moved predominately to issue a new [[CUSIP]] for the post-split [[shares]]. 
Q When would an [[ETF]]’s Portfolio [[ID]], formerly referred to as Instruction [[CUSIP]], change? 
A When the [[ETF]] has a corporate action event that necessitates a [[CUSIP]] change. However, it does  not 
change if the [[ETF]] has a trading symbol (ticker) or description change. 
Q Why would an [[ETF]]’s ticker symbol be unavailable in the PCF if it was there previously? 
A It could have been delisted in the case of [[liquidation]] or some other corporate action may have occurred.  
Q What does the [[ETF]] Classification Code represent in the Type 2: Portfolio Header Record?  
A The classification is at the [[ETF]] level. The values will include: [[Equity]], Fixed Income, Commodity, Mixed 
[[Asset]], Alternative and Currency. You will find a detailed description in the Key Definition section of this 
document. 
Q What [[DO]] the Component [[ID]] Codes in Field 6 of the Type 3 Detail Component Record represen t? 
A See the Detail Component Record = 3 in the Key Definition section. 
Q For the component undergoing a corporate action, under what circumstances is the C orporate 
Action indicator populated? 
A The Corporate Action indicator is provided as soon as [[DTCC]] receives information on the corporate 
action. Note: There are two indicators: one for a mandatory corporate action and one for a voluntary. An 
example of a mandatory would be a [[Stock]] split or name change. An example of a voluntary would be a 
tender offer. 
Q Are swaps, futures, non-deliverable forwards, and options included in the current version of the 
PCF equities and fixed income [[securities]]? 
A We will provide information on any [[NSCC]] and [[DTC]] ineligible [[securities]] that are not represented by a 
[[CUSIP]], ISIN, SEDOL, Bloomberg, Reuters, ICE/[[NYSE]] Liffe [[ID]] using the expanded Component [[ID]]  Code 
of “99”. The values of these ineligible components are represented by cash. Please keep in mind that the 
data is optional and dependent upon the product sponsor and [[ETF]] agent.

Q Does [[DTCC]] provide Undertakings for Collective Investments in Transferable [[securities]] (UCITS)? 
A No, because they are European listed ETFs, and we only provide U.S. listed ETFs that are registered 
under the [[Securities Act of 1933]], [[The Exchange Act]] of 1934, and the [[Investment Company Act]] of 1940. 
Q What is the definition of the External [[settlement]] Date? 
A The External [[settlement]] Date is an optional field that can be used by the [[ETF]] agent for foreign- based 
ETFs (designated as such on the PCF output) that are ineligible for creation or redemption through the 
[[NSCC]] automated process. If the components are ineligible to clear and settle at [[NSCC]] or [[DTC]], the 
agent uses this field to specify the number of business days the component should settle on. It was 
intended to assist ETFs that have components that settle in less than or greater than three business 
days. The field is a pass through and is not an edited field but must contain numeric. 
Q Why [[DO]] we receive [[ETF]] portfolios without any components? 
A They contain ineligible components that the [[ETF]] sponsor and agent decided not to include and are 
substituted for cash. These portfolios are referred to as cash based baskets. For example, inverse 
leveraged ETFs are always represented by cash to [[NSCC]]. 
Q Why would the component count in a portfolio be 0? 
A Because it is a cash only basket. 
Q What does the Sign field for the Component Quantity field in Type 3 Record in position 81 
represent? 
A This field is used for ETFs that are considered long or short funds. These components are intended to 
provide customers with what is essentially memo information and components identified as such cannot 
be part of the in-kind creation and redemption process unless they are substituted by cash. They are not 
very common. 
Q Why would we see a Component [[ID]] Code =4 and the Component [[ID]] of **********? 
A As it pertains to ******* it may occur in rare instances for ETFs designated as Foreign if the ISIN we are 
provided is U.S. based and eligible for limited depository service ([[DTC]]), for example pledging of 
[[securities]] for [[collateral]], but ineligible for clearance and [[settlement]] at the clearing corporation ([[NSCC]]) we 
can provide some information because it is a U.S. based ISIN. If it is a non-U.S. based ISIN, we don’t 
have any information that pertains to them nor the SEDOL and, therefore, accept or pass through what 
description is provided to us by the sponsor or agent. 
Q Can I reconcile Record Type 3, field 6 (Component [[ID]] Code) with the Record Type 2, Estimated T-
1 Cash Amount Per [[ETF]]? 
A As the 99 code is pass through information that we [[DO]] not validate; you may want to directly contact the 
[[ETF]] sponsor or an authorized [[participant]] (AP) that you use for your creation and redemptions for that 
information.

Q Why would I see multiple rows of the same component [[ID]] for the same [[ETF]] fund?  
A There are instances where because the currency is of such a small amount and the component quantity 
is large, for the sponsor to provide the total quantity of the basket’s component, they need to provide 
several records of the same component [[ID]]. Hence, the individual component is listed multiple times in 
the same basket. For the purposes of basket valuation or create/redeem processing, you should 
accumulate the same component’s [[ID]] within the specific [[ETF]] basket. 
Q Why does the Type 3, Component [[ID]] Code = 1 [[Option]] appear even though the Component [[ID]] 
contains an invalid [[CUSIP]]? 
A There are ETFs that are not create / redeem eligible through the [[NSCC]] automated process and the 
sponsor and agent want us to distribute the components of the [[ETF]] to APs and other users  of the PCF 
files even though the components are not [[NSCC]] and [[DTC]] eligible. In some instances, for example BKLN 
the PowerShares Senior Loan Portfolio [[ETF]] the sponsor and agent have decided to identify the [[ETF]] as 
a cash only portfolio so they can create and redeem through the automated process, and we can still 
distribute the components. 
Q Why does the Type 3, Component [[ID]] Code = 4 [[Option]] appear even though the first 12 characters 
of the Component [[ID]] contain an invalid ISIN? 
A There can be cases where because the [[ETF]] is not Create and Redeem eligible through [[NSCC]] and the 
component security, in this case the ISIN provided by the sponsor or [[ETF]] agent, is not validated 
because the security is ineligible at [[NSCC]] and [[DTC]]. 
Q Why does the Type 3, Component [[ID]] Code = 4 [[Option]] appear even though the first seven 
characters of the Component [[ID]] contain an invalid SEDOL? 
A [[NSCC]] does not validate SEDOL numbers. If the component does not have a registered ISIN or SEDOL 
number or if these are not specifically provided to [[NSCC]] by the [[ETF]] sponsor or agent, a U.S. ISIN may 
be listed rather than an ISIN identifier from a foreign venue. 
Q Why does the Type 3, Component [[ID]] Code = 4 [[Option]] appear even though an ISIN is designed in 
the Component [[ID]] field, not an ISIN/SEDOL? 
A [[ETF]] agents and sponsors [[DO]] not always provide a SEDOL and ISIN number for a component. If the 
component does not have a registered ISIN or SEDOL number or if these are not specifically provided to 
[[NSCC]] by the [[ETF]] sponsor or agent, a U.S. ISIN may be listed rather than an ISIN identifier from a 
foreign venue.

Q Why would an [[ETF]] fund be represented multiple times in the PCF file with slight variations in its 
name? For example, the addition of 02XXXXCR, 02XXXXRD in the [[ETF]] fund name. 
A Sponsors determine that the creation basket for authorized participants may need to be provided that is 
different than the tracking basket. These baskets have a recognized S&P [[CUSIP]] but have a symbol that 
is not utilized in the markets, for example AGGCR, which is the creation redemption basket for the 
iShares AGG the [[ETF]], whereas, CR means the creation basket. In many instances , there is also a 
redemption basket, which in the case of AGG would be AGGRD. Sponsors may use the multiple basket 
approach because obtaining all the components for creation and redemption can be difficult, yet the 
sample size of the creation and redemption baskets is sufficient to enable the [[ETF]] to correctly track the 
index. This scenario is referred to as the multiple basket approach and is not the same as custom 
baskets. 
If the [[ETF]] symbol contains characters that are unfamiliar, the client should reach out to the sponsor for 
clarification. 
Q Is there anything that [[DTCC]] can [[DO]] to so the fund does not change the submission format to 
satisfy the three-basket data model witnessed in Fixed Income baskets? 
A The multi-basket approach used by sponsors is under their control. If the fund decides it only needs a 
separate redemption basket and does not need a separate creation basket, that is their decision that 
they have most likely worked out with their authorized participants who create and redeem the [[ETF]] 
[[shares]] for [[secondary market]] trading. 
Q Why does the extension on the name of the PCF file change, e.g. 1256.C01 to 1256.C02?  
A The primary file will always have the extension C01 and the supplemental file will have the extension 
C02. 
Q Would there ever be an instance where the NAV per [[ETF]] does not match what the sponsor 
publishes (official NAV)? 
A [[DTCC]] receives and distributes the NAV per [[ETF]] that is sent from sponsor; however, if a distribution 
occurs, there is an adjustment made to this value. They should be used for calculation purposes only. 
The official NAV (unadjusted NAVs) file is sent separately to APs, vendors and sponsors for publication.  
Q If there is cash reflected in component level, should it be rolled up and reflected in the Est value 
of cash in lieu comp/CU in the portfolio/header record? 
A Yes.
