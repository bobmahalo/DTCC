CONTROL NUMBERS 
Introduction 
This topic describes transaction Control Numbers. 
Purpose 
Control Numbers are assigned by the clients and allow each transaction to be unique and identifiable.  The 
[[Member]] who initiates the transaction is the one who creates the Control Number. Th is Control Number will 
follow the transaction and all subsequent associated transactions in the Fund/SERV system.  
Control Number Rules 
Control Numbers (15 bytes long) are generated by clients who submit original transactions (i.e., firms for 
Record Type 001, funds for Record Type 007, TPA for Record Type 002 etc.). 
Normally, firms assign the Control Numbers and place their [[NSCC]] [[Member]] number in the first four bytes. This 
is because firms usually initiate the order process. However, a fund may generate a Con trol Number if they are 
the one initiating the order (i.e., Fund-Originated Orders) and they must place their [[NSCC]] [[Member]] number in 
the first four bytes. 
Control Number Format 
The correct format for a control number is: "ppppydddssssssc." 
The table below describes the components of the Control Number. 
Component Description 
pppp Originating [[participant]] (firm/fund) clearing number 
y Last digit of the year 
ddd Julian date 
ssssss Sequential number 
c Check digit using Modulus 10 Double Add Double 
algorithm (see section on Check Digital Calculation). 
 
 ACATS Control Numbers 
Control Numbers for ACATS transfers (Record Type 018) are generated by Fund/SERV. The correct format is 
"CATSAYDDDSSSSSS."

CHECK DIGIT CALCULATION 27 
CHECK DIGIT CALCULATION 
Check Digit Algorithm Rules 
Follow the steps in the table below to calculate a check digit for the Control Number, using Modulus 10 Double 
Add Double algorithm. 
Step Action 
1 Assign a position number to each digit of the Control Number according to its 
position in the Control Number as follows:  
• Odd Position: the assigned position number is 1 
• Even position: the assigned position number is 2 
2 Multiply each digit of the Control Number by its assigned position number.  
3 Add the multiplications.  
Note: If a multiplication is two digits long, add each digit separately to the sum.  
4 Subtract the last digit of the sum from 10. The last digit of the result (also called 10 
complement) is the check digit.  
Sample Calculation 
For this example, the first 14 bytes of a Control Number are: 13572028000037. Follow the steps in the table 
below to calculate the check digit (byte 15). 
Step Action 
1 Assign position numbers: 1212121212121212.  
 
2 Multiply each digit of the control number by its assigned position number:  
1 3 5 7 2 0 2 8 0 0 0 0 3 7 
X1 X2 X1 X2 X1 X2 X1 X2 X1 X2 X1 X2 X1 X2 
1 6 5 14 2 0 2 16 0 0 0 0 3 14 
 
3 Add the digits of the multiplication: 
1+6+5+1+4+2+0+2+1+6+0+0+0+0+3+1+4 = 36  
4 Subtract the last digit of the sum from 10: 10 – 6 = 4 
 
Result:  
The check digit is 4 and the whole control number is: 135720280000374.

FIXED LENGTH RECORDS 28 
FIXED LENGTH RECORDS 
Introduction 
This topic contains information on fixed length records. 
Description 
Each fixed length transaction consists of one or more 80-byte long records. 
Each 80-byte long record consists of two sections: 
• Control information (bytes 1-7), and 
• Data (bytes 8-80). 
 
The control information consists of the following fields: 
• Physical sequence number (bytes 1-2) 
• Logical sequence number (bytes 3-4), and 
• Filler (for future use) (bytes 5-7). 
Physical Sequence Number 
The physical sequence number of the first record in a submitted transaction must be 01 and shoul d increase by 
one (1) from record to record within the transaction. 
The physical sequence number of the last record in a submitted transaction must start with 9.  
Logical Sequence Number 
The logical sequence number within a submitted transaction must be in ascending order and cannot exceed 
the maximum allowed for that transaction (see record layouts). 
Example:  
The following are valid sequence numbers for registration: 
0101 0202 0303 0404 0507 0609 9710 
The last physical sequence number is 98 (rather than 08) to indicate that it is the last physical record of the registration. 
Logical sequence numbers 05 and 06 (optional records) are not included in this registration.

VARIABLE LENGTH RECORDS 
Introduction 
This topic contains information on variable length records. 
Purpose 
Data coming in through an interactive communication protocol must use the variable length record layouts.  
Note:  
Each variable length record is equivalent to one transaction and, therefore, can be transmitted as one message. 
Control Information Fields 
Each variable length transaction is one record. Bytes 1-11 are control information which consists of the 
following fields: 
• Record Length (Bytes 1-4) 
• Physical sequence number (Bytes 5-6) 
• Logical sequence number (Bytes 7-8), and 
• Filler (for future use) (Bytes 9-11). 
 
Note:  
Every section of 73 bytes thereafter is identical to the 73 bytes of data of the respective 80-byte fixed length record. 
Logical Sequence Number 
Since there can be only one physical record for each logical record, the 
• physical sequence number is always "01", and 
• logical sequence number is always "01."

Description 
Cash Adjustments may be submitted by a firm to debit or credit money from a fund. In turn, a fund could also 
submit a Cash Adjustment against a firm. 
[[settlement]] is based on the dollar value of all orders as confirmed or reconfirmed by the fund. In certain cases, 
the actual dollar value may differ from the confirmed dollar value on full redemptions, thereby requiring a Cash 
Adjustment. 
Cash Adjustments may be used for the following additional reasons: 
• gains and losses due to Extended Correction or As-Of processing 
• daily [[Dividend]] funds may continue paying a [[Dividend]] until [[settlement]] date  
• daily accrual funds that declare dividends daily but pay at the end of the month or quarter may have 
additional accrued dividends due that are not included in the balance of the account at the time of 
redemption 
• [[Dividend]] amounts that may be included in the confirmed dollar amount may also be paid directly to the 
[[investor]] on payment date, and 
• commission billing, commission adjustments, Contingent Deferred Sales Charge (CDSC) adjustments, 
and for long- and short-term capital gain adjustments.

settle on the Anticipated [[settlement]] Date in accordance with the [[Member]] Profile. A fund or firm's 
communication level will determine when Cash Adjustments are submitted and received.  
Firms send their Cash Adjustments in the firm stream. Funds send theirs in the fund stream. 
[[NSCC]] Edit Requirements

There are no time limitations between the submission of a Cash Adjustment and the original ord er.

Cash Adjustment is passed onto the firm. If the Cash Adjustment was submitted by the firm, it is forwarded to 
the fund.

Description 
Cash Adjustments may be submitted by a firm to debit or credit money from a fund. In turn, a fund could also 
submit a Cash Adjustment against a firm. 
[[settlement]] is based on the dollar value of all orders as confirmed or reconfirmed by the fund. In certain cases, 
the actual dollar value may differ from the confirmed dollar value on full redemptions, thereby requiring a cash 
adjustment. 
Cash adjustments may be used for additional reasons, such as: 
• daily [[Dividend]] funds may continue paying a [[Dividend]] until [[settlement]] date  
• daily accrual funds that declare dividends daily, but pay at the end of the month or quarter, may have 
additional accrued dividends due that are not included in the balance of the account at the time of 
redemption 
• [[Dividend]] amounts that may be included in the confirmed dollar amount may also be paid directly t o the 
[[investor]] on payment date, and 
• commission billing, commission adjustments, CDSC (Contingent Deferred Sales Charge) adjustments, 
and for long- and short-term capital gain adjustments. 
Timing 
Cash Adjustments are processed on the day they are received and, if not deleted by the contra side, they will 
settle on the Anticipated [[settlement]] Date in accordance to the [[Member]] Profile. A fund/firm communication 
level will determine when Cash Adjustments are submitted and received. Firms send their Cash Adjustmen ts in 
the firm stream. Funds send theirs in the fund stream. 
[[NSCC]] Edit Requirements 
Cash Adjustments may be sent anytime. They can be sent before or after [[settlement]].  
There are no time limitations between the submission of a Cash Adjustment and the original order. 
[[NSCC]] Action 
Cash Adjustments that satisfy the [[NSCC]] edits are passed on to the contra side. When submitted by a fund, it is 
passed on to the firm. If it was submitted by the firm, it is forwarded to the fund.

record that you may not normally receive. Under such circumstances, you will be aware of that record’s 
existence and will be able to discuss the transmission of that record with the originator.
