Overview 7 
1. OVERVIEW 
Information exchange and data communication consistently ranks as a top industry concern.  The mutual fund 
industry provides numerous communications regarding corporate actions, service disruptions and alerts that 
typically require broad communication from funds to their [[intermediary]] partners. Today, these industry 
communications are exchanged via fax, email, or phone calls.   
In 2018 [[NSCC]] launched MF Info Xchange – a centralized communications service for the mutual fund industry.  
The service facilitates and streamlines the delivery and receipt of time-critical notifications and helps to 
effectively organize, prioritize, and manage events and notifications through a centralized communications 
center.  MF Info Xchange eliminates the need to send faxes, emails, and phone calls as all communication 
activity will be performed by the service.  The service is available in the [[DTCC]] Portal.  
The development of this service is the product of collaboration with an industry working group, including [[DTCC]] 
clients and the Investment Company Institute (ICI), the leading association representing regulated funds 
globally. 
 
Benefits 
• Comprehensive portal supports many types of event notifications  
• Standardized communications, vetted by leading industry professionals 
• Eliminates lengthy and complex notifications with pre-defined and standardized set of data elements  
• Provides real time notifications to the parties as specified by the deliverer 
• Seamless integration with Mutual Fund Profile Security database minimizes keystrokes and the risks 
associated with manual entry. 
• Dashboard provides a view into items requiring immediate attention 
• Notification audit trail provides a consolidated view of all modifications, distribution history, including the 
list of email addresses for the event notification since its creation.  
• Comprehensive audit trail for client activity within Company Information, Distribution List and 
Undeliverable/Automatic Response sections 
• Event Calendar provides clients with a view into date-critical events, tracks historical event details, and 
reminds receivers of upcoming events, all in one place. Never miss an event again!  
• Ability for notification receivers to designate email recipients by Event Type  
• Notification Approval Workflow supports a four-eye review principle    
• Delivers operational efficiencies to notification submitters and receivers 
• No coding required 
• API capabilities allow clients to automate their event communication process, customize dat a extraction, 
and achieve straight-through processing directly to and from their internal system(s).

4.1.2 Notifications with Undeliverable Emails/Automatic Replies 
This section provides information on the latest distribution/redistribution of a notification with any failed 
distributions and/or receipt of automatic replies.  
The “Total Number of Undeliverable Emails / Automatic Replies” column will display the total number of email 
addresses that sent undeliverable or automatic replies. The “Number of Unresolved Undeliverable Emails / 
Automatic Replies” column will display the number of email addresses that haven’t been acted upon by the 
user. 
 
Note:  
If the notification was distributed multiple times using Distribute/Redistribute to All/Redistribute to New functionality, this 
notification/Event [[ID]] might be listed multiple times in this view if each distribution/redistribution activity resulted in a receipt 
of undeliverable or automatic reply emails. For example, if Event [[ID]] 123 was distributed as “Initial Notification” on 
November 1st , Redistributed to All on November 5th, Redistributed to New on November 10th and distributed as an 
“Update” on November 15th, the above table will have the following entries for this Event [[ID]]:  
- One entry on November 1st (if any emails were returned as undeliverable or automatic replies) 
- Additional entries will be added on November 5th and November 10th for Redistribute to All and Redistribute to New 
activities respectively (if each of these redistribution activities resulted in a receipt of undeliverable/automatic reply emails).  
- On November 15th, the entries from November 1, November 5 and November 10 will be replaced with one new entry from 
the November 15th distribution of this event if any emails were returned as undeliverable or automatic replies. The list of 
undeliverable/automatic replies will represent the emails received in response to the November 15th distribution and might 
be different from the lists received on November 1st, November 5th and November 10th.  
 
Clicking on the Event [[ID]] will display the “Undeliverable Emails/Automatic Replies Details” screen with a list of 
all emails that were returned as undeliverable or sent automatic replies.

4.2 Company Profile 
4.2.1 Company Information 
Clients creating and delivering a notification have the ability to load and store their organization’s attributes 
(company logo, company URL and legal disclaimer) within the MF Info Xchange portal.  This information is 
optional and will not prevent the client from sending notifications through MF Info Xchange.  Clients c an load 
all, one or a combination of these data elements, save and update/delete them at any time.  This data will be 
used at the time when a client is distributing a notification.  These elements (if loaded through the portal) will be 
appended to the notification.  If this information is not stored in the system at the time of notification distribution, 
the notification will be distributed without this information. [[NSCC]] recommends clients add their company logo 
in one of the following formats: .png, .svg, .gif, .jpg, .jpeg, .bmp, .tiff up to 1 MB. 
 
Note:  
Changes to the company information will not update previously distributed notifications but will be included in new 
notifications or updated notifications as this information will be pulled from the database when the revised or new 
notification is being previewed and distributed by the deliverer.   
 
Clicking on the “Company Information Audit Trail” icon will take clients to the Company Information Audit Trail 
page where updates to Company Logo, Company URL and Legal Disclaimer will be displayed with a date and 
time stamp of the change under a separate header.

Best Practice:  
In order to streamline communication process and ensure distribution to all relevant parties, members of the working group 
recommend utilizing group email address or group distribution list (e.g. group@firm123.com) instead of individual email 
addresses when creating distribution lists.  The receiving firms, who would provide the group address/distribution list, would 
also manage individual access to their group email address within their firm. For example, group@firm123.com would 
include name1@firm123.com, name2@firm123.com, and name3@firm123.com.  Following this best practice will 
reduce the number of returned or failed emails.  
All MF Info Xchange distributions will be sent from MFIX_Notifications@[[DTCC]].com email address.  Depending on the 
notification receiver’s mail server settings, some organizations may only send one automatic reply email even if multiple 
emails are sent to an email address with “Out of the office” [[Option]] turned on. In the event multiple event notifications (from 
the same or multiple fund [[Companies]]) are sent to the same email address (person@firmabc.com) and this person’s 
mailbox is turned on with an “Out of Office” auto response, the first distribution will receive this auto reply, other event 
distributions will not receive the same message.  This will result in only one notification showing this auto reply on the 
“Undeliverable Emails/Automatic Replies Details” page which displays returned and automatic replies.   
 
Following the aforementioned best practice will avoid the exceptions outlined in the above scenario and will reduce the risk 
of key/relevant parties within the receiver’s organization not getting the email communication.

4.10 Notifications – Best Practices 
4.10.1 [[DO]] NOT Re-use Notifications 
New events/notifications must be created/sent via a NEW notification/Event [[ID]] (use “Create” Notification menu 
[[Option]]) instead of updating an old event [[ID]]. Each event type must be tracked via its own Event [[ID]] (for audit trail 
and communication purposes). Clients are advised to create new notifications (instead of re-using old 
notifications/Event IDs).  
Alternatively, clients can clone an existing notification which will be assigned a new Event [[ID]].  
 
4.10.2 Event Status 
All New notifications must be created with “Event Status” =” Initial Notification”.

7. NOTIFICATION APPROVAL WORKFLOW  
In order to utilize the Approval Workflow, “All notifications must be submitted for approval” field must be 
checked within the “Company Information” screen. If this field is checked, the approval workflow will be turned 
on. All notifications for your organization will follow the approval process. Organizations that [[DO]] not require 
an approval workflow process, are advised to leave this field blank. The Approval Workflow is available to 
both fund and firm clients. 
Users provisioned with the “Update” role will be able to create/update notifications  and will be required to 
submit notifications for review and approval.  
Users provisioned with the “Approve” role will review and approve or reject notifications. Approved notifications 
will then be distributed to the designated receivers once the approver clicks the “Approv e” button.  
Rejected notifications will not be distributed to the receivers. Users with the “Update” role will need to revise a 
rejected notification and re-submit for approval. 
 
 
• The “All notifications must be submitted for approval” field will NOT be checked. Clients wishing to utilize 
the approval workflow must click the checkbox to turn on the approval process.  
 
• Only users provisioned with the “Approve” role can turn the approval workflow on or off. In order to  utilize 
the approval workflow, at least one user at the organization must be provisioned with the “Approve” role.  
• The approval workflow cannot be turned off until all notifications that are pending approval have been 
reviewed and approved/rejected. 
• Users provisioned with the “Approve” role can create/update/distribute/approve/reject notifications.  
• Notifications created or updated by a user with the “Approve” role [[DO]] not require a review by another 
approver.  
Notes:  
Approval workflow (if turned on) will be bypassed when creating/updating/deleting/distributing notifications via API calls.

8. DATA RETENTION 
In accordance with the [[DTCC]] records management policy, MF Info Xchange automatically purges all 
notifications and their associated parameters (notification data, audit trail, distribution history, undeliverable 
emails) 5 years after the notification was last updated (updated or distributed/redistributed). Once purged, the 
notification will no longer appear on the submitter’s and receivers’ portals/API calls and can no longer be 
retrieved, reviewed, and/or searched for.

4. [[DO]] I need to use my current communication process to send notifications to organizations that are

5. How [[DO]] I communicate multiple events in one notification? 
MF Info Xchange clients can send various notifications through MF Info Xchange.   In order to provide 
clear and consistent communications to the notification receivers, each event must be communicated as a 
separate notification using the relevant event type.  For example, a fund company might be undergoing a 
Fund Merger between two of their funds as well as a Hard Close for another fund.  In  order to streamline 
communications and avoid confusion on the receiving side, these events must be communicated as two 
separate notifications using the appropriate event type: 
• 1st notification: Event Type = Fund Merger 
• 2nd notification: Event Type = Fund Close – Hard Close

Comment field.

enhancement request to [[NSCC]].
