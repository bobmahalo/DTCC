REVIEWING VARIANCES  
Variances are discrepancies between a data point value in a filed document and the data point value populated 
in MFPS. Clients with appropriate permissions can review and address all variances in the Review Variances 
page. This is the [[default]] page when a fund client logs into the system. The navigation panel provides 
navigational access to the page from the Review Variances sub-menu item under Data. The Unaddressed 
Variances link on the Quality Index Score page also provides access to the Review Variances page.  
The Review Variances page contains two sections: 
• Open Variances - indicates variances where the Fund is required to take action. 
• Processed Variances - indicates variances that have been reviewed and resolved; either as a 
resolved mapping issue, an annotated variance, or an accepted variance. 
 
All information within these sections can be sorted or filtered by typing in the available search criteria. Each 
variance is assigned a variance [[ID]] to allow for tracking within the UI.   
 
All information within these sections can be exported to an Excel workbook by clicking the Download button 
next to the specific table. 
Open Variances 
Open variances are listed in two sections:   
• Outstanding variances – indicates newly identified variances.  These variances appear as 
“unaddressed variances” on the Quality Index reports.  Once the variance is approved or annotated as 
a mapping issue or acceptable variance, it is removed from this section and placed under the 
Processed Variances tab.  
• Mapping Issue Returns - indicates those variances reviewed and determined by [[DTCC]] not to be a 
mapping issue.  Funds need to remove the mapping issue by either accepting the new data point value 
or annotating it as an acceptable variance.   
All information within these sections can be sorted or filtered by typing in the available search criteria.

Fund Detail Levels  
Frequently, a fund client needs to update a multiple [[SEC]] urity Issue IDs with the same change at the same time. 
MFPS employs an inheritance model that defines how data is inherited from parent to child entities.  Profile 
Security is a hierarchical database with four distinct levels where data elements at each child level can be 
inherited from a parent level. The four hierarchical levels are as follows: 
1. The Management Company level information serves as a [[default]] for all the fund's Security Issue IDs.
